## 一、特效：Cobblemon 的能复用，而且比想象中完整

我查了它的资源目录，三类东西都能用：

### 1.1 招式粒子（完整可用）

`assets/cobblemon/bedrock/particles/moves/` 下，我们四个技能需要的都在：

| 技能 | 可用粒子 id |
| --- | --- |
| Q 喷射火焰 | `cobblemon:flamethrower_actor`（喷出）、`flamethrower_target`（命中）、`flamethrower_targetburst`（命中爆开）、`flamethrower_target_linger`（残留） |
| W 火焰旋涡 | `cobblemon:firespin_actor`（漩涡主体）、`firespin_actorburst`、`firespin_actorcinder`、`firespin_target` |
| R 大字爆炎 | `cobblemon:fireblast_actorshoot`（发射）、`fireblast_actor1`、`fireblast_actor2`、`fireblast_target`（爆炸）、`fireblast_targetcinder` |
| E 飞翔 | **无专属粒子**（飞行是变化类招式）。用原版 `CLOUD`/`CRIT` 或借 `infestation_actorflydisperse` 的拖尾感 |

**怎么调起来**（已核实 API）：

```java
// 1. 从仓库按 id 拿特效定义
BedrockParticleOptions effect =
    BedrockParticleOptionsRepository.getEffect(ResourceLocation.parse("cobblemon:flamethrower_actor"));

// 2. 客户端：直接生成
ParticleStorm.createAtPosition(clientLevel, effect, pos).spawn();

// 3. 或服务端发包：包一层 SnowstormParticleOptions，走原版 sendParticles
level.sendParticles(new SnowstormParticleOptions(effect), x, y, z, 1, 0, 0, 0, 0);
```

### 1.2 模型动作（能用，但没专属招式动作）

喷火龙的模型动画里**没有** flamethrower / fireblast 这类名字，只有通用动作：

```
special / air_special / physical / recoil / battle_idle / ground_idle / sleep / cry ...
```

Cobblemon 自己的战斗特效也是这么回退的 —— `action_effects/moves/flamethrower.json` 里写的是：

```json
{"type": "animation", "animation": ["flamethrower", "fire", "spray", "special"]}
```

前三个在喷火龙身上不存在，**实际播放的就是 `special`**。

所以我们也照抄这个策略：**喷火/旋涡/大字爆炎都用 `special`，飞翔用 `air_special`**，再配合粒子区分。

### 1.3 音效（完整可用）

`assets/cobblemon/sounds/move/` 下：

| 技能 | 音效 |
| --- | --- |
| Q | `cobblemon:move.flamethrower.actor` / `.target` |
| R | `cobblemon:move.fireblast.actor` / `.target` |
| E | `cobblemon:move.impact_generic.flying_1~8` 里挑一个 |
| W | 用 Q 的 actor 音效降低音调，或复用 flamethrower 音 |

### 1.4 每个技能的最终特效配方

| 技能 | 释放 | 命中 |
| --- | --- | --- |
| Q | `special` 动作 + `flamethrower_actor` 每 0.6 秒喷一次 + actor 音效 | `flamethrower_targetburst` + target 音效 |
| W | `special` 动作 + `firespin_actor` 常驻 + 每 0.5 秒 `firespin_actorburst` | `firespin_target` |
| E | `air_special` 动作 + 原版 `CLOUD` 拖尾 | 命中时 `CRIT` + 飞行冲击音 |
| R | `special` 动作 + 蓄力时 `fireblast_actor1/2` 聚气 + `fireblast_actorshoot` 发射 | `fireblast_target` 爆炸 |

### 1.5 风险（必须提前说）

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| `BedrockParticleOptions` 是共享实例 | 它内部带摩拉变量（位置、朝向），多个风暴同时用同一个实例可能串味 | 每次生成前 `copy()` 一份，或验证它的变量是按 storm 存的 |
| `ParticleStorm` 是客户端类 | 服务端不能直接调，要走 `SnowstormParticleOptions` 发包 | 走发包，顺便省得两端各写一套 |
| 粒子需要"朝向"参数 | 喷火是定向的，粒子的 target_deltaz 需要设 | 用风暴的 target 参数传入朝向向量 |
| E 没有专属粒子 | 效果不如其它三个 | 用原版粒子 + 动作补足，可接受 |

## 二、UI：4 套宝可梦风格方案

**共同前提**

- 进入上帝视角时，**隐藏原版底部 UI**（物品栏、血量、饥饿、经验条）
  - 做法：mixin 掉 `Gui.renderHotbarAndDecorations`，一个注入点全隐藏
- 我们的技能栏画在原本物品栏的位置（左下/底部）
- 全部用 `GuiGraphics` 纯代码绘制，不引入资源包

---

### 方案 1 ·「GBA 复古」

参考《火红/叶绿》的下屏面板：米白底、双线描边、硬阴影。

```
┌──────────────────────────────┐
│ ████████████████░░░░  302/360│  ← 绿色分段血条（每段 10%）
└──────────────────────────────┘
 ┌────┐ ┌────┐ ┌────┐ ┌────┐
 │ 火 │ │ 旋 │ │ 飞 │ │ 爆 │    ← 米白方块 + 深灰双线边框
 │  Q │ │  W │ │  E │ │  R │      属性色小色块在左上角
 └────┘ └────┘ └────┘ └────┘
  ●●●●●●●○○○  7/10             ← 像素圆点
```

- **配色**：底 #F8F0D8、描边 #4A4A4A、文字 #303030、血条绿 #58C848
- **冷却**：深灰斜纹遮罩 + 白色数字
- **优点**：最像宝可梦，一眼认出来；实现最简单（全是矩形）
- **缺点**：在 3D 世界里略显“贴纸感”
- **工作量**：小（2~3 小时）

---

### 方案 2 ·「剑盾/朱紫 现代」

深色半透明圆角面板 + 属性色发光，贴近当代宝可梦 UI。

```
╭──────────────────────────────╮
│ ▰▰▰▰▰▰▰▰▰▰▰▱▱▱▱▱▱▱  302/360 │  ← 圆角血条，绿→黄→红渐变 + 外发光
╰──────────────────────────────╯
  ◉    ◉    ◉    ◉             ← 圆形图标 + 环形冷却
  Q    W    E    R
 ◉◉◉◉◉◉◉◉◉○  9/10              ← 环形能量槽
```

- **配色**：面板 rgba(12,16,28,0.78)、描边 rgba(255,255,255,0.25)、属性色发光
- **冷却**：**环形饼图遮罩**（绕图标转一圈），中间白色数字
- **优点**：最好看，最有“正式对战界面”的感觉
- **缺点**：要画圆、渐变、环形遮罩，代码量最大
- **工作量**：中（5~6 小时）

---

### 方案 3 ·「卡片式技能卡」

每个技能一张小卡片，信息最全。

```
┌────────────────────────────────────────────┐
│  302 / 360   ████████████░░░░░░            │
└────────────────────────────────────────────┘
┌─────────┐┌─────────┐┌─────────┐┌─────────┐
│▔▔▔▔▔▔▔▔ ││▔▔▔▔▔▔▔▔ ││▔▔▔▔▔▔▔▔ ││▔▔▔▔▔▔▔▔ │ ← 属性色顶条
│  喷射   ││  旋涡   ││  飞翔   ││ 大字爆炎 │
│  火焰   ││         ││         ││  蓄力中  │
│ 3点 2.0s││ 3点 1.2s││ 2点 就绪││ 5点 0.4s│
└─────────┘└─────────┘└─────────┘└─────────┘
      ●●●●●●●○○○  8/10
```

- **配色**：卡片深灰 rgba(30,30,34,0.9)，顶条按属性（火 #F08030 / 飞 #A890F0）
- **冷却**：卡片整体压暗 + 底部进度条 + 剩余秒数文字
- **优点**：技能名、耗点、CD 全写在脸上，新手最友好
- **缺点**：占地最大，遮挡画面最多
- **工作量**：中（4~5 小时）

---

### 方案 4 ·「极简 HUD」

没有面板，只有图标和环，最大化视野。

```
                              ◉Q  ◉W  ◉E  ◉R      ← 右下角一行小图标
                                                    环形冷却
 ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁         ← 底部一条细血线
    ●●●●●●●○○○                              ← 技能点：小圆点
```

- **配色**：无面板；图标半透明，属性色描边；血线纯色
- **冷却**：图标整体变灰 + 环形细进度
- **优点**：最不挡视野，适合上帝视角看战场
- **缺点**：信息密度低，技能名看不到（只能靠位置记），不像“宝可梦风格”
- **工作量**：小（2~3 小时）

---

### 四套对比

| | 宝可梦味 | 信息量 | 遮挡画面 | 工作量 |
| --- | --- | --- | --- | --- |
| 1 GBA 复古 | ★★★★★ | ★★★ | 中 | 小 |
| 2 剑盾现代 | ★★★★☆ | ★★★☆ | 中 | 大 |
| 3 卡片式 | ★★★☆ | ★★★★★ | 大 | 中 |
| 4 极简 | ★★☆ | ★★ | 小 | 小 |

**我的建议：方案 1**。理由：你要的是“宝可梦风格”，GBA 复古最认得出；而且它全用矩形绘制，最不容易出渲染 bug，交付最快。等玩法验证完，再升级到方案 2 也不迟。

## 三、隐藏原版 UI 的做法

```java
@Mixin(Gui.class)
public abstract class HudMixin {
    @Inject(method = "renderHotbarAndDecorations", at = @At("HEAD"), cancellable = true)
    private void pkmoba$hideVanillaHud(GuiGraphics g, DeltaTracker t, CallbackInfo ci) {
        if (GodView.isActive()) ci.cancel();
    }
}
```

这一处就能隐藏：物品栏、血量、饥饿、护甲、经验条。左上角的我们自己的调试 HUD 不受影响（那是另一个渲染回调）。

## 五、需要你定的两件事

### U1 · 选哪套 UI
- **1 GBA 复古** · 推荐
- **2 剑盾现代**
- **3 卡片式**
- **4 极简**
- 或 **「先 1 后 2」**：先用 1 快速验证，验收通过再升级到 2

### U2 · 特效复用程度
- **A 全量复用**：粒子 + 动作 + 音效全用 Cobblemon 的 · **推荐**
- **B 粒子复用，动作/音效用原版的**（更稳，但没那么像原版战斗）
- **C 只用音效，粒子用原版**（最稳，效果一般）
