- 方案版本：2.0（覆盖 v1）

- 平台：Minecraft 1.21.1 + Fabric + Cobblemon 1.8.2

| # | 需求 | 说明 |

## 2. 队伍制对战规则（N2 的落地形式）

### 2.1 规则

- 每名玩家持有 **一支宝可梦队伍**（当前 = 已实装的全部种族：喷火龙、水箭龟；上限先设 6，代码留扩展位）。
- 对战时**同一时刻只有一只上场**（和现在"一人控一只"的控制模型一致，不破坏上帝视角与 QWER 输入）。
- 上场的宝可梦阵亡 → 延迟 2 秒（40 tick）后在**己方宝可梦点位**自动放出队伍里下一只；切换期间该玩家无宝可梦可操作，但不会被判负。
- **一方队伍全部阵亡 → 该方判负**，对局结束。
- 玩家本人不参战、不受伤；玩家死亡/退出按离场判负处理。

### 2.2 为什么不做"全部同时上场"

- 现有输入（右键移动、QWER、左键普攻）全部指向"当前受控的那一只"，同时上多只需要再做一套多选/切换/编队 UI，成本高且容易和现有 HUD 冲突。
- 队伍制天然支持"打光全部宝可梦"，且以后加宝可梦只是往队伍里加一项。

> 如果你想要"两只同时在场、可以切换控制"，告诉我，我改成多实体+切换键方案（工作量约多一倍）。

### 2.3 队伍顺序与首发

- 开局选择界面选定的是**首发宝可梦**。
- 队伍里其余宝可梦按种族注册表顺序排后面。
- `/mo team` 可查看队伍顺序（只读展示，改动顺序放到后续版本）。

## 3. 数据层

### 3.1 玩家档案 `PlayerProfile`（SavedData，主世界）

```
speciesId        首发种族（默认 cobblemon:charizard）
chosen           是否完成开局选择
fainted          非对战时是否处于"队伍全灭待复活"
teamOrder        队伍种族顺序（List<ResourceLocation>，默认 = 全部已实装种族，首发置前）
```

持久化：`server.overworld().getDataStorage().computeIfAbsent(...)`，key `pkmoba_players`。

### 3.2 场地档案 `ArenaStore`（SavedData，主世界）

```
name             场地名（如 "场地一"）
redPlayerPos     红方玩家落点
bluePlayerPos    蓝方玩家落点
redPokemonPos    红方宝可梦落点
bluePokemonPos   蓝方宝可梦落点
dimension        维度（四点必须同维度）
radius           战斗活动半径（默认 = 四点包围盒外扩 8 格，可用指令改）
```

持久化 key：`pkmoba_arenas`。

### 3.3 种族注册表

```java
public record SpeciesEntry(ResourceLocation id, String nameKey, ResourceLocation portrait) {}
private static final List<SpeciesEntry> SPECIES = List.of(
    new SpeciesEntry(CHARIZARD_ID, "pkmoba.species.charizard", pkmoba("textures/gui/pokemon/charizard.png")),
    new SpeciesEntry(BLASTOISE_ID, "pkmoba.species.blastoise", pkmoba("textures/gui/pokemon/blastoise.png")));
```

加新宝可梦 = 加一项 + 技能表 + 一张 32×32 头像贴图。战斗分支继续用 `Skill.isBlastoise(pokemon)` 选技能表，不动战斗内核。

## 4. 开局选择与更换宝可梦

### 4.1 开局选择

```
玩家进服
  -> 读档案；!chosen 则 S2C StarterListPayload(可选种族 + 已选)
  -> 客户端开 StarterScreen（米黄面板 + 卡片网格：32×32 头像 + 名字）
  -> 点选 -> C2S StarterChoosePayload(speciesId)
  -> 服务端校验白名单 -> 写档案（speciesId + teamOrder 首发置前）-> 换实体
```

### 4.2 更换

- `/mo pokemon` 打开同一界面；`/mo pokemon <species>` 直接切换（带补全）
- 道具「宝可梦切换器」右键打开界面

### 4.3 HUD 徽章

技能面板左上角加 20×20 当前出战宝可梦头像 + 名字。

## 5. 对战场地点位系统（N3）

### 5.1 两个道具

| 道具 | 右键（不蹲） | 潜行+右键（蹲下） |
|---|---|---|
| 玩家点位放置器 `player_marker` | 设置**蓝方玩家点** | 设置**红方玩家点** |
| 宝可梦点位放置器 `pokemon_marker` | 设置**蓝方宝可梦点** | 设置**红方宝可梦点** |

- 点位的记录对象是**执行右键的玩家自己**（每人一份草稿，互不干扰）。
- 位置取右键命中的方块顶面中心（`BlockPos.above()` 中心），并做落地安全检查。
- 每次放置给聊天反馈：「已记录 红方玩家点 (x, y, z)」，并记下维度。
- 蹲下判定用 `player.isShiftKeyDown()`。

### 5.2 创建场地

```
/mo arena create <名字>
```
- 校验：该玩家四个点都放过、同一维度、红蓝玩家点间距 ≥ 8、红蓝宝可梦点间距 ≥ 8。
- 通过则写入 `ArenaStore`，聊天反馈「已创建场地：场地一」。
- 相关子命令：
  - `/mo arena list` 列出所有场地
  - `/mo arena delete <名字>`
  - `/mo arena info <名字>` 打印四点到坐标
  - `/mo arena radius <名字> <半径>` 改活动半径
  - `/mo arena clear` 清空自己草稿里的四个点
- 兼容：原 `/mo arena <半径>` 保留为"临时场地半径"，不删。

### 5.3 发起对战

```
/mo duel <玩家> <场地>
/mo duel consent
```
- `<玩家>` 补全在线玩家名；`<场地>` 补全 `ArenaStore` 里已创建的场地名。
- 邀请里带上场地名；接受时若场地已被删除 → 提示并拒绝。
- 不写场地时给提示：「请指定场地：/mo duel <玩家> <场地>」，不默认任何一个。

### 5.4 开局流程（接受后）

1. 校验双方不在其它对局、档案齐全、场地存在且同维度。
2. 先 `teleportTo`：发起者 → 红方玩家点，接受者 → 蓝方玩家点（含朝向互相对视）。**必须在开启上帝视角之前传送**，否则 `PlayerLockService` 会把玩家锁回原位。
3. 双方 `ServerGodMode.setActive(true)`（此时锁的是新落点）。
4. 按各自队伍首发放出宝可梦到红/蓝宝可梦点，注册归属。
5. `CharizardCombat.setArena(四点心点, 场地 radius)`。
6. 广播：「1v1 开始：A（喷火龙） 对战 B（水箭龟），场地：场地一」。

### 5.5 结束流程

- 判负/主动退出 → 双方 `setActive(false)`（会自动回进入前位置），清空宝可梦实体，解注册，清 HUD。
- 平局规则保持：双方同时全灭 → 平局。

## 6. 队伍切换（N2 落地）

### 6.1 状态

对局内维护：

```
MatchSide { UUID player; List<ResourceLocation> team; int index; UUID activeEntity; long respawnAtTick; }
```

- `index` = 当前出战在队伍中的下标。
- 当前实体阵亡 → `activeEntity=null`，`respawnAtTick=now+40`，聊天提示「你的喷火龙倒下了，准备放出下一只…」。
- 到点：`index++`；若 `index >= team.size()` → 该方全灭判负；否则在己方宝可梦点放出 `team[index]`。

### 6.2 非对战（训练模式）

- 队伍全灭 → 档案 `fainted=true`，提示 `/mo revive` 或去治疗机。
- `/mo revive`：在玩家位置满血放出首发。
- 治疗机（`cobblemon:healing_machine`）：`UseBlockCallback` 命中且该玩家 `fainted` → 执行同一套复活，并放行原版治疗。

## 7. 对战 UI（N4）

### 7.1 布局（宽 214，高 42，位于技能面板正上方）

```
┌──────────────────────────────────────────┐
│ [16×16 玩家头]  玩家名                    │   y+4
│ [32×32 宝可梦头]  ██████████░░  72/100  水箭龟 │   y+20
└──────────────────────────────────────────┘
```

- 第一行：16×16 玩家头像（皮肤）+ 玩家名。
- 第二行：24×24 宝可梦头像（缩放的 32×32 贴图）+ 血条（宽 120，高 6）+ `72/100` + 宝可梦名。
- 右下角小圆点表示对手队伍剩余只数（可选，便于看懂"打光才算赢"）。

### 7.2 玩家头像

- `Minecraft.getInstance().getConnection().getPlayerInfo(uuid)` → `PlayerInfo.getSkin().texture()`。
- 回退链：`DefaultPlayerSkin.getDefaultSkin(uuid)` → 灰色底块。
- 绘制：优先 `PlayerFaceRenderer.draw(ctx, texture, x, y, 16)`；无此类则 `blit` 两段
  皮肤 UV `(8,8,8,8)` 脸 + `(40,8,8,8)` 帽子层，放大到 16×16。

### 7.3 宝可梦头像

- 新增 `tools/generate_pokemon_portraits.py`，与现有技能图标同风格（米黄底 + 深棕描边 + 像素色块），
  生成 `assets/pkmoba/textures/gui/pokemon/charizard.png`、`blastoise.png`（32×32）。
- HUD 里按 24×24 绘制。

### 7.4 Payload

## 8. 喷火嘴部 + 粒子（N5，沿用 v1）

- 服务端 `jetRay` 原点：`getEyePosition()` 沿 `dir` 前移 0.45、下移 0.15，贴近嘴部。
- 客户端 `FlameJetEffects`：取 `mouth` locator，距离权威原点 ≤ 1.5 格时**以 mouth 为射线原点**重新布点；删掉原来的 5 颗桥接特例。
- 粒子：`scale 0.9 + rand*0.6`、`lifetime 5 + rand(3)`、`rays 56`；墙余量按新 scale 收紧。

## 11. 风险与边界

1. **传送顺序**：必须"先传送再开上帝视角"，否则锁定服务会把玩家拉回原坐标。
2. **实体复用**：对战用玩家自己那只实体；若玩家把它带到很远，会被传送到宝可梦点，提示里要说明。
3. **场上无宝可梦的空窗**：切换 40 tick 内该玩家无操作对象，HUD 显示"准备中"。
4. **SavedData 迁移**：老存档首次读会生成默认档案（喷火龙首发、队伍=全部已实装种族）。
5. **离线皮肤**：离线模式可能拿不到皮肤，回退默认头像。
6. **场地维度**：只允许同维度对战，跨维度直接拒绝并提示。
7. **不动的部分**：Q/W/E/R 数值、技能表结构、上帝视角、锁定服务本次不改。
