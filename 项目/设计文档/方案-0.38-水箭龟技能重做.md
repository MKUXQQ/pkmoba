# 方案-0.38-水箭龟技能重做

- 适用版本：0.37.0 → 0.38.0
- 状态：设计方案 v3，待确认（§15 三项）后实现
- 修订记录：
  - v1：槽位重排（水炮→Q、旋转→W、冲浪→E）、旋转清钉、冲浪术
  - v2：删除水之刃；原「冰山坠落」改造为 R 槽「喷水」（扇形 + 减速）；重做水球外观
  - **v3：喷水改为「前摇 → 扇形区域大量水滴密集砸落」，不再是三颗大水球；水滴小、数量多、持续 2 秒**

## 1. 需求原文与拆解

### 1.1 第一轮（v1 依据）

> 现在我发现水箭龟这个精灵太厉害了。他的r技能范围太远了，而且伤害还高。并且我发现他的e技能不能中断，他会一直到处转圈。我不希望他的高速旋转当成一个位移技能来用，因为后面要加入清钉子的机制，所以我想将这个高速旋转变为清钉子的作用。我的想法就是把高速旋转变成跟走路差不多的速度。然后增加他的攻击判定范围。把他的r技能换到q技能上，然后把E技能的高速旋转换到w技能。然后再把e技能变为水箭龟所拥有的冲浪术。这个冲浪术我希望是水箭龟踏浪而行。

### 1.2 第二轮（v2 依据）

> 我需要把水之刃给删除掉，因为我觉得这个技能不符合水箭龟在动画里的技能。他原本的技能冰山坠落，我觉得很像水箭龟喷水这个技能。我希望加强这个冰山坠落的范围，并且把它名字改为喷水。我想更改喷水这个技能，把它改为像前面一个扇形。砸下原本的那个水球模型，但是我觉得那个水球模型是圆形的，不太好看。我现在需要更像水球的方案。如果被这个r技能喷水砸中的话，就会进入减速状态。

### 1.3 第三轮（v3 依据，本版重点）

> 我希望不是三个水球一次砸落，我希望是一个扇形，很多个水球砸下去。他有一定的前摇，他是技能放出去之后，然后后面再有水滴砸下去。这个水滴我希望多一点，密集一点砸下去。

## 2. 现状诊断（0.37.0）

### 2.1 当前四技能实测参数

| 槽 | 名称 | 射程 | 伤害 | 时长 | 耗点 | CD |
| --- | --- | --- | --- | --- | --- | --- |
| Q | 水之刃（穿透弹） | 18 格 | 14（每目标一次） | 飞行约 18 格 | 3 | 40t |
| W | 冰山坠落 | 12 格落点、半径 3 | 16 | 下落即爆 | 3 | 40t |
| E | 高速旋转 | 自身位移最多 60 格 | 2×10 = 20 | 100t（5s） | 2 | 40t |
| R | 加农水炮 | 24 格、半径 2 | 7×5 = 35 | 蓄力 16t + 输出 40t | 4 | 40t |

基础：血量 340（喷火龙 280）、普攻 5 / 16t、资源 10 点、每 20t 回 1 点。

### 2.2 为什么"太厉害"（仍成立）

1. **远程安全输出**：R 24 格、Q 18 格，喷火龙 Q 只有 10 格锥形、R 20 格且要近身收尾。
2. **血厚**：340 血比喷火龙多 21%。
3. **旋转是"位移+输出+还能继续放技能"三合一**：0.6 格/tick（约 12 格/秒）×100t，期间还能放 Q/W。
4. 一轮技能总伤 85，而对方只有 280 血。

### 2.3 为什么旋转"不能中断、自己到处转圈"

- `BlastoiseCombat.tick()` → `channel == 3` → `tickSpin()`；`skillTicks >= 100` 才 `endChannel()`，除到时间外**无任何取消入口**。
- `tickSpin()` 自驱位移：`entity.move(MoverType.SELF, direction.scale(Math.min(0.6, 平面距离)))` + `turn(entity, 18)`。
- 同时 `MoveOrderService.tickEntity()` 在 `CharizardCombat.blocksMovement(entity)` 为 true 时直接 `navigation.stop(); return;`（MoveOrderService.java:126）→ 玩家的右键移动点被丢弃。
- 结论：不是 bug，是"旋转独占位移权 + 忽略玩家输入"的设计后果。

### 2.4 "圆形水球"从哪来（R10 根因）

- 服务端 `BlastoiseCombat.explodeDrop()`（:348-360）与 `tickDrops()`（:327-346）：W 在落点上空 6 格生成 `Drop`，每 tick 下坠，`visual(kind = 2, length = 剩余高度, radius = 1)` 持续刷新。
- 客户端 `WaterEffects.render()`（:189-198）：`kind == 2 && length > 0` → `sphere()`；`length <= 0` → 落地 `ring()`。
- `sphere()`（:310-321）用 **20×40 个四边形拼一个正球体**，红色通道按纬度渐变，贴图是 `pkmoba:textures/effect/water_smooth.png`（:28）。
- 观感问题：正球体 + 纬度渐变 = "玻璃球/肥皂泡"，没有水流方向、没有形变、落地没有过渡。
- 结论：**不是贴图问题，是几何 + 缺少动态形变的问题**；v3 进一步改为"大量小水滴"，用数量与密度取胜。

## 3. 设计目标

1. 水箭龟从"安全远程炮台 + 5 秒高机动"回落为"厚血中程战士 + 少量控制"。
2. 高速旋转 = 走路速度的持续判定场 + 清钉子工具，随时可中断。
3. 冲浪 = 11 格左右、18 伤、有重量感的位移技能。
4. 喷水 = 身前扇形（14 格长、±30°）内**前摇 0.5 秒后开始降雨**，持续 2 秒密集砸下大量水滴；命中减速。取代水之刃成为第 4 技能。
5. 水滴外观重做：小水滴形（上尖下圆）+ 拖尾 + 落地小水花，靠数量读出"喷水"。
6. 喷火龙与既有对战流程零回归；协议只新增 1 个 S2C payload。

### 5.2 W 高速旋转（原 E）

| 项 | 0.37 | 0.38 |
| --- | --- | --- |

| 位移 | 自驱 0.6 格/tick，最多 60 格 | **零自驱**；交给正常移动指令，速度 = 走路（`NAV_SPEED = 1.2`） |
| 朝向 | 服务端 `turn(entity,18)` 持续转向 | **服务端不再改 yaw**；旋转只由客户端 `ShellAnimator` 表现 |
| 判定半径 | `inflate(0.4)` | **`inflate(1.3, 0.6, 1.3)`**（横向有效直径约 3.4 格） |
| 伤害 | 每 10t 2 点，共 20 | **每 10t 1 点，共 8** |
| 清钉 | 无 | **起手 + 每 20t 调 `HazardService.clearNear(pos, 3.0)`** |

| 期间放技能 | 可放 Q/W，禁 R | **一律禁**（施放任意技能都先中断旋转） |

**实现要点（决定是否还会"自己跑"）**

1. `blocksMovement()` 改为 `channel == CANNON || channel == SURF || channel == SPOUT`（旋转不再阻塞移动指令）。
2. 删除 `tickSpin()` 中 `MoveOrderService.getTarget` / `entity.move` / `turn` 三段，只保留每 4t 水花、每 10t 判定、每 20t 清钉。
3. 服务端不调整 yaw，导航按正常路径把宝可梦带到右键点 → 玩家获得"边走边转"，速度与平时完全一致。
4. 客户端 `WalkAnimator:74` 已用 `ShellAnimator.appliesTo(...) && ClientState.getChannel() == 3` 触发旋转姿态，无需改。
5. `castCore` 删除 `castWhileSpinning` 与 `if (channel == 3 && skill == Skill.R) return;`，改为：`if (channel == SPIN && skill == Skill.W) { interruptSpin("toggle"); return; }`；其余技能先 `interruptSpin("cast")` 再正常施法。

**中断矩阵**

| 事件 | 结果 |
| --- | --- |
| 再按 W | 立即结束（不扣点、不进 CD） |
| 施放 Q / E / R | 先结束旋转，再正常施法 |
| 玩家按 C 换人 / X 收回 | 结束旋转并清表现 |
| 实体死亡 / 被移除 / 对局结束 / 退出上帝视角 | `endChannel()` + 客户端清表现 |

### 5.4 R 喷水（v3 重做：前摇 + 扇形密集降雨 + 减速）

#### 5.4.1 定位

- 取代被删除的水之刃，成为第 4 技能：**身前扇形区域 → 前摇 0.5s → 持续 2s 大量水滴密集砸落 → 命中减速**。
- 与 Q「加农水炮」区分：Q 是直线蓄力炮（高伤、单线、可躲）；R「喷水」是覆盖型控制（范围、持续、减速、有前摇可躲）。
- 名称：喷水（Water Gun）；Q 仍叫加农水炮（Hydro Cannon）。

#### 5.4.2 几何：扇形区域

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 扇形长度 | **14 格** | 原冰山坠落落点 12 格，加强到 14 |
| 扇形半角 | **30°**（全角 60°） | 远端横向张开约 ±8 格 |
| 扇形锚点 | 施法瞬间的自身位置 + 鼠标水平朝向 | 释放后区域固定，玩家可走开，水滴继续落 |
| 落点采样 | 距离 `d ~ U(2.5, 14)`、角度 `θ ~ U(-30°, 30°)` 均匀采样 | 每次落点重采样，避免规则纹样 |
| 最小间距 | 同一波内 1.2 格 | 最多重采样 8 次，防重叠成"大块水" |

#### 5.4.3 时间线（前摇 + 降雨）

```
t=0     施放：扣 4 点，进 CD 60t，锁定朝向，channel = SPOUT(6)
        t=0~10：前摇 10t（0.5s）
          - 水箭龟定身：blocksMovement = true、blocksBasicAttack = true
          - 炮口聚水粒子、身体后仰、蓄水音效
          - 地面扇形水膜提前亮起（telegraph，青色 → 临近释放转亮白）
          - 可被击杀/换人/对局结束打断，打断则不产生降雨
t=10    释放：channel 归 0（恢复移动/普攻/可接其它技能）
        t=10~50：降雨 40t（2s），共 20 波，每波 8 颗，合计 160 颗水滴
          - 每波间隔 2t，波内 8 颗落点在扇形内随机
          - 水滴从 6~9 格高空以 0.45→0.75 格/tick 加速下落，落地耗时约 0.5~0.9s
          - 落地：小水花 + 泡沫 + 半径 0.8 判定
t=50    降雨结束；地面扇形水膜再残留 10t 渐隐
```

- **前摇是刻意设计**：给对手 0.5s 反应时间（走出扇形 / 交位移），符合"范围控制"的定位。
- **释放后不占用 channel**：水箭龟可以边走边看雨，降低"放完技能站着挨打"的挫败感；但由于降雨期间的伤害有上限，不会变成"免费输出"。

#### 5.4.4 伤害与减速（上限机制）

| 项 | 值 |
| --- | --- |
| 单颗水滴伤害 | **1 点**（落地半径 0.8 内） |
| 每目标整轮上限 | **20 点**（即最多被 20 颗水滴命中，之后不再掉血） |
| 命中计数 | `Map<UUID, Integer>`，新一次施法清空 |
| 减速 | 首次命中施加 `MOVEMENT_SLOWDOWN` **等级 II（−30%）60t**；后续命中只刷新时长到 60t，**等级不叠加** |
| 作用对象 | `BasicAttack.validTarget` 过滤后的实体（宝可梦/玩家） |
| 穿墙 | 不算穿墙：落点必须有 `clearLine(施法者→落点)`，被墙挡住的落点直接取消该颗水滴 |
| 耗点 / CD | 4 / **60t** |
| 落空 | 雨照下、水花照出，只是没目标 |

> 为什么用"1 点 × 上限 20"而不是"每颗大水球 20"：v3 要的是"很多、密集"，如果每颗都高伤就变成秒杀；用上限机制让画面密集但总伤恒定，也方便后续只调一个数字做平衡。

#### 5.4.5 与 v2（三球）和 0.37（冰山坠落）的差异

| 项 | 0.37 冰山坠落 | v2 三球 | v3 密集降雨 |
| --- | --- | --- | --- |
| 落点 | 鼠标点地，单点 | 3 个固定落点 | 扇形内 160 个随机落点 |
| 前摇 | 无（直接落） | 无 | **10t（0.5s）** |
| 持续 | 单次 | 14t 内 3 次 | **40t（2s）持续降雨** |
| 范围 | 半径 3 | 扇形并集 | 扇形 14 格 / ±30° 全覆盖 |
| 伤害 | 16 | 20（每目标一次） | 1 × 上限 20 |
| 减速 | 无 | 无（v2 才加） | II −30% 3s，持续刷新 |

## 6. 视觉效果方案：水滴 + 扇形降雨（R10/R11 重点）

### 6.1 为什么现在的球不像水

1. **几何**：`sphere()` 是完美正球体（20 纬 × 40 经），任何角度看轮廓都一样 → 玻璃球。
2. **光照**：`entityTranslucentEmissive` 全亮 + 只有纬度渐变，没有高光/内部流线/边缘泡沫。
3. **动态**：下落只改位置和半径，没有拉伸/压扁/拖尾 → 没有速度与重量。
4. **交互**：落地从球直接切成 ring，没有炸开的过渡。

### 6.2 候选方案（v3 采用 V1 小水滴 + 密度）

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **V1 小水滴网格（采用）** | 旋转体生成"水滴"外形：上部收尖、下部饱满、底部内收 0.2；半径 0.14–0.26（随机）；下落沿速度方向拉伸 1.5×，拖 3 段尾迹 quad | 轮廓是水滴不是球；小尺寸 + 高数量 = 雨 | 顶点量靠数量堆，需要 LOD |
| V2 大团圆簇 | 大主球 + 卫星球 | 适合单发命中 | v3 不再需要（数量已经够） |
| V3 卡通贴图 | 128×128 水滴贴图 billboard | 成本最低 | 侧面看是纸片 |

### 6.3 降雨表现（客户端本地生成，不逐颗发包）

**关键决定：服务端只在释放时发 1 个 `SpoutPayload`（锚点 + 朝向 + 时长 + 种子），客户端用同一随机种子在本地复现 160 颗水滴。**
理由：逐颗发包 160 条约 8KB，且要处理丢包；本地生成零网络成本、零丢包，伤害仍由服务端独立结算（视觉与判定轻微不同步可接受）。

| 阶段 | 客户端表现 |
| --- | --- |
| 前摇 0–10t | 地面扇形水膜由暗到亮（telegraph）；炮口两处（`cannon1`/`cannon2` locator）聚水粒子；屏幕外远处的玩家只看到扇形微光 |
| 每波（2t） | 本地从种子生成 8 个落点（d/θ 均匀采样、间距 ≥1.2），每颗水滴：初始高度 6~9 格、下落 0.45→0.75 加速、半径 0.14–0.26、轻微横向抖动 |
| 落地 | 4 颗 `ParticleTypes.SPLASH` + 小泡沫环（半径 0.8，8t 渐隐）+ 短促水声（同波最多 2 次，避免音效过载） |
| 持续期 | 地面扇形水膜保持 0.3 透明度，随波次轻微脉动 |
| 结束 | 水膜 10t 内渐隐；最后一波落地后再留 4t 水雾 |

**性能预算**

- 单帧最多同屏约 56–64 颗水滴（2s 内 160 颗、单颗可见 ~0.7s）；
- 每颗水滴 LOD：8 纬 × 6 经 ≈ 48 quad（不是 800 quad 的完整水滴）→ 峰值约 3000 quad，与现有水炮 / 冲浪网格同级，可接受；
- 距离 >96 格不渲染；同屏水滴硬上限 80。

### 6.4 三个"读范围"的提示

1. **前摇期**：地面扇形水膜（telegraph）——对手能看见自己是否站在范围里；
2. **降雨期**：落点水花 → 玩家能感受到"哪里在被喷"；
3. **结束后**：水膜 10t 残留 → 确认刚才的覆盖区。

### 6.5 贴图与颜色（复用现有资源）

- 继续用 `pkmoba:textures/effect/water_smooth.png` 做 UV，无需新美术资源；
- 颜色分层（顶点色）：内核 `(120, 200, 255, 235)`、外壳 `(200, 240, 255, 120)`、水滴尖/泡沫 `(235, 250, 255, 200)`；
- 如需更"水"的质感，0.39 再补一张 `textures/effect/water_droplet.png`。

## 7. 状态机与中断模型

### 7.1 channel 常量（数值不改，只改语义）

```java
private static final int CHANNEL_NONE   = 0;
private static final int CHANNEL_CANNON = 4; // 原 R 水炮 → 现在 Q
private static final int CHANNEL_SPIN   = 3; // 原 E 旋转 → 现在 W
private static final int CHANNEL_SURF   = 5; // 新增，E 冲浪
```

保留 3/4 的原因：客户端 `SkillHud`（:335/:338）、`SkillKeys`（:31-32）、`WalkAnimator`（:74/:88）都硬编码了 `channel == 3` / `== 4`；改数值等于同时改协议语义，收益为零。

### 7.2 客户端 channel → 技能槽映射（必须同步改）

| channel | 0.37 含义 | 0.38 含义 | 修改点 |
| --- | --- | --- | --- |
| 4 | R（水炮蓄力进度） | **Q（水炮蓄力进度）** | `SkillKeys:32` → `return 0;`；`SkillHud:338` → `i == 0` |
| 3 | E（旋转） | **W（旋转）** | `SkillHud:335` → `i == 1` |
| 5 | — | **E（冲浪）** | `SkillKeys` 加 `if (channel == 5) return 2;`；`SkillHud` 加 `i == 2 && channel == 5`；`WalkAnimator` 加冲浪姿态 |
| 6 | — | **R（喷水前摇）** | `SkillKeys` 加 `if (channel == 6) return 3;`；`SkillHud` 加 `i == 3 && channel == 6` 进度条（0→1，10t） |
| 1 | 喷火龙 Q | 不变 | — |

### 7.3 耗点表按物种

```java
// Skill.java
private static final int[] CHARIZARD_COSTS = {3, 3, 2, 4};
private static final int[] BLASTOISE_COSTS = {4, 2, 3, 4}; // Q水炮 / W旋转 / E冲浪 / R喷水

public static int cost(PokemonEntity pokemon, int index) { ... }
public static int cost(String speciesId, int index) { ... }
```

- 服务端：`BlastoiseCombat.castCore` 用 `Skill.cost(entity, skill.ordinal())` 替换 `skill.cost`。
- 客户端：`SkillHud:314` 已按实体取；`SkillHud:508` 与 `SkillPresentation.cost(int)`（:18-19）只按 index 取枚举值，需改成按当前物种取。

### 7.4 中断与清理

- 只在 `BlastoiseCombat.State` 内实现 `interrupt(reason)`，禁止外部直接改 `channel`。
- `channel` 结束动作：`channel = 0; skillTicks = 0;` + 客户端表现收尾（`visual id 0` 或 `SpoutPayload` 的 cancel 标记）。
- **降雨不是 channel**：前摇被中断 → 直接取消降雨；降雨开始后被中断（死亡/换人/对局结束）→ 取消剩余水滴，已经落地的伤害保留。
- 对局结束、`resetAll()`、`TeamService.unregisterIfCurrent` 都走同一入口；区域状态 `Spout` 一并清空。

### 7.5 状态机示意

```
              ├─ 区域 Spout 建立，降雨 40t（可自由行动）

              └─ 前摇被打断 → 取消；降雨中被打断 → 取消剩余水滴
```

## 13. 风险与对策

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 降雨视觉与判定不同步 | 客户端本地生成、服务端独立结算 | 种子一致 + 落点由服务端下发的锥体参数决定；误差 ≤1 格可接受 |
| 160 颗水滴掉帧 | 峰值约 3000 quad | 单颗 LOD 48 quad、同屏硬上限 80、>96 格不渲染；仍掉帧则把每波 8→6（总伤上限不变） |

| 前摇 0.5s 手感拖沓 | 定身会让人不适 | 前摇只 10t；释放后立刻自由行动；如果实测难受可降到 6t |
